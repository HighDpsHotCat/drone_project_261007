# ESP32-S3 / STM32H743 연동 규약

이 저장소는 Android 앱입니다. ESP32-S3 및 STM32 펌웨어는 포함하지 않습니다.
아래 UUID와 명령 형식은 앱 구현을 위해 정한 규약이며, 기존 펌웨어의 규약을 확인한 값이 아닙니다.
기체 펌웨어를 동일하게 구현해야 검색 이후 조종 서비스 연결과 영상 수신이 가능합니다.

## BLE

Nordic UART Service 형식을 사용합니다. 광고 이름은 `Drone-S3` 등을 권장하며 이름으로 검색을 제한하지 않습니다.

| 항목 | UUID | 필수 속성 |
| --- | --- | --- |
| 서비스 | `6e400001-b5a3-f393-e0a9-e50e24dcca9e` | Primary |
| Android → ESP 명령 RX | `6e400002-b5a3-f393-e0a9-e50e24dcca9e` | Write with response |
| ESP → Android 상태 TX | `6e400003-b5a3-f393-e0a9-e50e24dcca9e` | Notify, CCCD `0x2902` |

앱은 GATT 연결, 서비스 확인, CCCD 등록이 모두 성공해야 연결 완료로 표시합니다.
이는 비행 제어기의 준비/무장 상태를 보증하지 않습니다. OS Bluetooth 본딩은 별도이며 앱은 강제로 본딩하지 않습니다.
상태 알림은 짧은 UTF-8 문자열로 보내면 화면 하단에 표시됩니다. 예: `BAT 82% | ALT 0.8m | DISARMED`.
기본 ATT MTU 23에서도 명령은 들어갑니다. 상태 문자열은 협상된 MTU 안에 들어가도록 제한하세요.

### 명령: 12바이트, little endian

| 오프셋 | 크기 | 의미 |
| --- | --- | --- |
| 0 | 2 | ASCII `DC` (`44 43` hex) |
| 2 | 1 | 버전 `1` |
| 3 | 1 | 모드: `0` 위치·고도 유지 요청, `1` 이동 속도 요청, `2` 비상 정지 요청 |
| 4 | 2 | unsigned 16-bit 순번, 65535 다음 0 |
| 6 | 2 | signed 16-bit 전후 속도, +전진 / −후진 |
| 8 | 2 | signed 16-bit 좌우 속도, +오른쪽 / −왼쪽 |
| 10 | 2 | signed 16-bit 수직 속도, +상승 / −하강 |

각 속도는 `−1000..1000`의 정규화 값입니다. 펌웨어에서 검증된 최대 m/s로 환산하세요.
명령 주기는 50ms(20Hz)이며 손가락 입력 시 즉시 갱신합니다. GATT 쓰기는 하나씩 처리하며 대기 명령은 최신 값 하나만 유지합니다.
축 방향은 기체 기준입니다. yaw/회전 조종은 이번 화면에 포함하지 않았습니다.
두 스틱을 동시에 사용할 수 있고, 한 스틱을 놓아도 다른 축 입력은 유지합니다.
양쪽을 놓으면 모드 0, 속도 0입니다. 뒤로가기, 앱 일시 중지 시에도 모든 축을 0으로 되돌립니다.
비상 정지 후에는 재연결 전까지 앱 입력을 잠급니다. 펌웨어의 비상 정지는 재연결만으로 해제되지 않도록 별도 잠금과 재무장 조건을 구현하세요.

### 펌웨어에서 구현할 동작

- 연결만으로 모터를 무장하거나 시동하지 마세요. 이 앱에는 무장·시동 절차가 아직 없습니다.
- GATT 응답은 ESP 수신 확인입니다. STM32가 명령을 적용했다는 확인이 아닙니다.
- ESP가 명령을 STM32로 전달하고, STM32가 ICM42688-P/BMP390/VL53L1X/PMW3901을 융합해 자세·고도·위치를 제어해야 합니다.
- 중립 명령은 모터 출력 0을 의미하지 않습니다. 현재 위치/고도 유지 목표로 전환하는 요청입니다.
- 이동 중에는 목표 속도를 추종하고, 중립으로 전환될 때 현재 추정 위치/고도를 새 목표로 잡으세요. 매 패킷마다 유지 목표를 다시 잡으면 위치가 흐를 수 있습니다.
- STM32 자체에 명령 타임아웃을 두세요(초기 벤치 테스트 예: 마지막 유효 명령 후 300ms). 연결 단절, ESP 재부팅, 앱 정지는 수신 누락으로 처리하세요. 센서 유효성과 비행 상태에 맞는 유지/착륙/정지 동작을 별도로 설계해야 합니다.
- 비상 정지 모드의 실제 동작은 펌웨어에서 구현해야 합니다. 앱은 전달 시도만 보장하며 끊어진 무선 링크로 명령 전달을 보장할 수 없습니다.
- 입력 범위, 패킷 길이·버전·순번, 센서 유효성, 배터리 및 무장 상태를 확인하세요.

## OV3660 영상

ESP32-S3에서 PSRAM을 사용하고 `esp32-camera`의 `PIXFORMAT_JPEG`으로 시작하세요.
초기 권장 설정은 VGA 640×480, 약 10~15fps입니다. BLE와 Wi-Fi 동시 사용 시 실측 지연·끊김에 맞춰 조정하세요.
보드의 정확한 카메라 GPIO 배치는 보드 모델에 맞게 설정해야 합니다.

- ESP AP 예: SSID `Drone-S3`, IPv4 `192.168.4.1`.
- 영상 서버 예: `http://192.168.4.1:81/stream`.
- 응답: HTTP 200, `Content-Type: multipart/x-mixed-replace; boundary=frame`.
- 각 파트에 JPEG 프레임, `Content-Type: image/jpeg`, `Content-Length`와 CRLF를 넣으세요.
- 앱은 영상 주소를 변경할 수 있지만 사설 IPv4의 HTTP/HTTPS만 허용하며 HTTP 리다이렉트는 따르지 않습니다.
- 앱은 현재 Wi-Fi 네트워크에 영상 요청을 직접 보냅니다. 인터넷 없는 기체 AP에 연결해도 이동통신망으로 영상 요청이 빠지지 않도록 합니다. VPN 정책과 휴대폰의 Wi-Fi 유지 설정도 실제 기기에서 확인하세요.
- 영상 실패는 BLE 조종 연결을 끊지 않습니다. 녹화 중 영상이 끊기면 녹화를 마무리합니다.

## 녹화

휴대폰에서 받은 JPEG를 H.264/MP4, 640×480, 목표 10fps, 약 1.5Mbps로 인코딩합니다.
전송 중 실제 수신 프레임에 따라 프레임 속도가 낮아질 수 있으며 오디오 녹음은 없습니다.
프레임 대기열은 최신 한 장만 유지하여 조종 UI를 막지 않습니다.
Android 10 이상은 갤러리 `Movies/DroneController`에 저장합니다.
Android 8~9는 앱 전용 Movies 폴더에 저장하며 공유 버튼으로 내보낼 수 있습니다.
추가 저장소/마이크/카메라 권한은 요청하지 않습니다. 인코더 지원 여부는 휴대폰에서 검증해야 하며 실패 시 앱에서 원인을 표시합니다.

## 휴대폰 검증 순서

1. 프로펠러를 분리한 벤치 환경에서 앱을 설치합니다.
2. 기체 Wi-Fi에 연결한 다음 앱으로 돌아와 블루투스 권한을 허용하고 기기를 검색합니다. Android 8~11은 위치 권한과 위치 서비스도 필요합니다.
3. 기기에 연결합니다. 호환 서비스가 없으면 오류를 표시하고 컨트롤 진입 버튼은 비활성 상태여야 합니다.
4. 컨트롤 화면에서 영상 수신, 좌우 스틱의 개별/동시 입력, 손을 뗐을 때 0 명령, 대각선 범위 제한을 확인합니다.
5. BLE 로그/STM32 UART 로그로 실제 패킷과 명령 타임아웃을 확인합니다. 모드 0이 모터 정지로 잘못 해석되지 않는지 확인합니다.
6. 녹화 시작/중지 후 MP4 재생과 공유, 영상 중단 시 저장 완료 또는 오류 표시를 확인합니다.
7. 뒤로가기는 기기 연결 화면으로 돌아가면서 BLE 연결을 유지하고 중립 명령을 계속 전송합니다. 연결 해제는 중립 명령을 우선 전송한 후 GATT를 닫습니다.
8. 홈 버튼/화면 잠금/다른 앱 전환 시 중립 요청·연결 해제, BLE 전원 끄기/권한 거부/재연결, 가로·세로 화면 전환을 확인합니다.

클라우드에서는 APK 빌드와 JVM 테스트를 수행할 수 있습니다. 실제 BLE, Wi-Fi 영상, 인코더, 센서 기반 위치 유지와 비행은 실기기 검증 항목입니다.
